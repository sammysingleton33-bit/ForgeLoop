# Lessons learned — experience (FORGE-04)

Format: date · lesson · evidence · tag (`observed-once` / `repeated` / `standard`). Verified entries only.

- 2026-10-12 · Luau interpolated strings cannot contain a literal `{ ... }` (for example an error message like `` `must be { min, max }` ``): the compiler reports "Malformed interpolated string, got ','" and the whole module fails to load. Rephrase, or escape the brace as `\{`. · Lune 0.11 spec run: `SoundRegistry.luau:102: Malformed interpolated string`; fixed in SoundRegistry, VfxPresets and Onboarding · `observed-once`
- 2026-10-12 · In spec helpers that merge overrides into defaults, `field = nil` in a table literal does **not** clear the default (the key is simply absent), so a "missing field" case silently tests the default. Use a sentinel (`noAsset = true`, `burst = false`) or build the case without the helper. · two failing specs (Audio "has an asset, so status cannot be 'needed'", Vfx "expected 50 to be 100") before the fix · `repeated`
- 2026-10-12 · Lune cannot answer engine-only reads like `Sound.IsPlaying` or `Sound.TimeLength` ("Failed to get property 'IsPlaying' - missing default value"), and `roblox.implementProperty` does not override them. `implementMethod` works for `Sound:Play/Stop` and `ParticleEmitter:Emit`. Keep backends behind a tiny interface and replace only the engine read in specs. This confirms the integration lesson about reflected properties. · `roblox/tests/unit/experience/doubles/EngineStubs.luau`; Audio specs 15/15 after the change · `repeated` (with docs/lessons-learned/integration.md)
- 2026-10-12 · A mutation pass (break one rule, expect its named spec to fail) found a real gap that a green suite hid: `Pacing:observe` could drop its minute fallback with every spec still passing. Run `python3 roblox/tests/unit/experience/mutations.py` after adding rules. · 27/28 caught on first run, 28/28 after adding the "observe uses the clock too" spec · `observed-once`
- 2026-10-12 · A framework service that lists a service in `dependencies` cannot boot in a game project that does not ship that service. game-001's boot gate (`games/game-001/tests/integration/Boot.spec.luau`) failed on SettingsService → DataService for that reason. Optional collaborators belong in `registry:find(...)` inside `start()`, with a documented fallback (D-027 session store). The same gate caught AudioController parenting SoundGroups to a SoundService that MockEnv does not provide as an Instance, which is now guarded by `backend.available()`. Run the game-001 specs, not only the framework specs, before opening a framework PR. · `check.sh` step "game-001 specs" red before, PASS after (5/5 boot specs) · `observed-once`
- 2026-10-15 · The mutation runner replaces the **first** occurrence of a row's `old` text. When a later change copies that line elsewhere in the same file (#137's `hoverAt` repeated `_resolve`'s `pcall(entities.pick, …)`), the row silently mutates the wrong function and reports NOT CAUGHT, or worse, CAUGHT by an unrelated spec. Give rows text that is unique in the file (indentation or a neighbouring line), and rerun every task's rows on a file you touch, not only your own task's. · FL-0090 15/16 on main after #137 → 16/16 after the row matched only `_resolve`'s two-tab line (#143) · `observed-once`
- 2026-10-15 · Never run a mutation pass in a worktree whose full gate is running: mutations rewrite source files in place, so the gate may test a mutant. Queue them, or use separate worktrees. · an FL-0121 gate overlapped a mutation run on the same worktree and was discarded and re-run · `observed-once`
- 2026-10-15 · Read Selene's full summary, never `selene … | tail -1`: the last line can be a clean "0 parse errors" while the lines above report errors and warnings. · #123's gate failed on Selene after a local check that only looked at the tail · `observed-once`
- 2026-10-15 · Screen-edge GUI placed from camera projections must use the GUI's own area: `Camera:WorldToScreenPoint` (GUI-inset space, like `AbsolutePosition` and taps) minus the ScreenGui's `AbsolutePosition`, within its `AbsoluteSize`. Full-viewport pixels from `WorldToViewportPoint` put badges under the top bar or off a phone's safe area. · B16 request badges: the first phone render lost the bottom-left badge; correct after the change (renders `requests-edge-*.png`; headless renderer only, Studio **unverified**) · `observed-once`
