## Process notes
- A conflicted PR gets no CI (no merge ref): #217 showed no check runs at all until FORGE-02 merged main. A READY needs a check run on the head.
- When a PR's tests depend on another PR's behaviour (#219 on #218) its body must say "merge after"; my check is to run the PR's own specs on main alone and with the dependency.
- A stacked PR's head-to-head diff includes whatever its branch merged from main (#223 against #222: 205 files; GitHub's file list for #223 was too large to read). I take the PR's own files from its commits and its own diff against its base, and run each PR on its own base. When FORGE-01 merges main into the stack the four heads move together without changing any PR-owned file: I compare blob ids of the owned files before re-verifying.
- The mutation runners change the tree in place. A probe or spec run in the same worktree sees a live mutant (a spec I had not touched failed 50 against 53); stopping a runner with `pkill` skips its restore. Probes run on their own worktrees; a runner is left to finish.
- Claims in my own comments get checked after posting: one said "checked below" for a merge check I had not yet run, one said I opened three desktop renders when it was two; both corrected in a follow-up comment.
- I never state a full SHA from memory: the API rejected one I mistyped and I used `git rev-parse` (the earlier slip is the same rule).
